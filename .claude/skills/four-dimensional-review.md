# four-dimensional-review

在 PR 通过初审（规模检查 + 规范合规检查 + 高风险扫描）后，对其进行四维度评审。高风险代码的正确性已在 Step 2.5 由 Codex-reviewer 专项检查，此处仅做低风险区域的常规正确性检查，不重复覆盖高风险区域。

## 输入

- PR Diff 内容
- PR 描述
- PR 元数据（ID、标题、作者、变更文件列表）

## 执行步骤

### 1. 四维扫描

逐文件逐行扫描变更，每一条评审意见（无论打回还是建议）必须锚定到具体变更行，按四个维度评估：

| 维度 | 关注点 |
|---|---|
| **正确性** | 逻辑是否正确、边界是否覆盖、有无并发/竞态问题、外部输入是否验证 |
| **可读性** | 命名是否表意、结构是否清晰、有无魔法数字、函数长度是否合理 |
| **可维护性** | 有无重复代码、职责是否单一、是否引入不必要依赖、测试覆盖度 |
| **可演进性** | 是否过度耦合、扩展点是否封闭、有无破坏向后兼容 |

### 2. 输出问题清单

标注严重等级（打回/建议），按维度归类，每条问题格式：

```markdown
| `[文件路径，行号]` | 问题描述 | 维度 | 严重等级 |
```

### 3. 综合结论

- 存在打回项 → 最终结论：**❌ 打回**，列出打回理由及改进建议
- 存在建议项但无打回 → 最终结论：**✅ 通过（附建议）**
- 无问题 → 最终结论：**✅ 通过**

## 约束

- 遵循 fail-open 原则，拿不准一律当建议不打回
- 每条评审意见按 `[文件名，行]` 格式定位
- 禁止对注释、格式化、空格等低风险变更打回
- 禁止脑补未出现的信息
