# markdown-geshihua

在 PR 评审输出完成后，对最终报告进行 Markdown 格式化检查与修正。

## 格式化规范

### 标题层级

- 报告总标题用 `#`（单 `#`）
- 流程步骤标题用 `##`（如 `## Step 1 — 规模检查`）
- 子标题用 `###`（如 `### 最终结论`）
- 4 级标题用 `####`（如 `#### 四维评审`）
- 标题前后保留空行

### 表格格式

- 表头与分割线之间无空行
- 分割线使用 `|---|---|---|`
- 内容列左对齐
- 空值用 `—` 表示
- 表格前后保留空行

### 代码与行号

- 评审意见中的文件定位使用：`` `[文件路径，行号]` ``
- 代码片段用单个反引号包裹
- 多行代码用 ``` 代码块包裹

### 高亮与状态

| 符号 | 含义 |
|---|---|
| `✅` | 通过 |
| `❌` | 拒绝 / 打回（含打回理由） |
| `⏸` | 待补充 |

### 列表格式

- 列表使用 `- ` 短横线，无需有序号
- 同层级列表缩进一致（2 空格）
- 子列表缩进 4 空格

### 空行与分段

- 不同段落间保留一个空行
- 表格、代码块前后各留一个空行
- 列表与后续段落之间保留一个空行

### 段落与标点

- 每条评审意见单行描述，以句号或分号结尾
- 无列表项说明
- 结论性语句用粗体：`**拒绝**`、`**打回**`、`**通过**`

## 检查清单

输出格式化后，检查以下项目：

1. 标题层级是否正确、连续
2. 表格对齐、段落分隔符是否正确
3. 文件定位格式统一为 `` `[文件，行]` ``
4. 状态符号使用正确
5. 列表缩进一致
6. 空行数量正确
7. 全文无多余空格或错误换行
