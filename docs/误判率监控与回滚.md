# 误判率监控与回滚机制

## 定位

自动评审可能误判（该过的打回、该打回的放行）。本机制量化误判、暴露告警、提供回滚通道，防止规则失效长期累积。

## 一、数据流

```
每次评审
  └─ appendRecord → production/data/review-records.json（decision + 打回）
打回被推翻（override 标签）
  └─ override.ts → markOverridden(prId) → 该记录 humanOverridden=true
误判率 = 被推翻的打回 / 总打回数
  └─ checkMisrateAlert() → 超阈值（默认 15%）写 misrate-alert.txt
```

- 每次评审自动写入 `review-records.json`（agent 编排的 index.ts）
- 打回记录落 `rejected/{PR-ID}.md`
- workflow 每次运行把 `review-records.json`、`rejected/`、`misrate-alert.txt` 提交回仓库，保证跨 CI 运行累计

## 二、误判率告警

- `checkMisrateAlert(threshold = 0.15)`：打回数 ≥ 5 且误判率 > 15% 时触发
- 触发时 agent 编排输出告警并写 `misrate-alert.txt`
- workflow 提交该文件入库，可在仓库中持续追踪

## 三、单 PR 回滚（override）

开发者认为打回有误时：

1. 在被打回的 PR 上添加 `override` 标签
2. CI 的 override job 触发：`override.ts` 标记 `humanOverridden=true` 并删除 `rejected/{PR-ID}.md`
3. 贴评论确认"已接受人工推翻"
4. 该 PR 计入误判率（分子），用于后续规则调整

## 四、规则级回滚（误判率高时）

误判率告警说明规则或阈值过严，需人工介入调整：

| 误判原因 | 回滚动作 |
|---|---|
| 阈值太严（如加权分 < 3.0 偏高） | 调低 escalate 阈值 |
| 规则太严（某条规则频繁打回合理 PR） | 修订对应 `RULE-*.md`，或降为 warning |
| 高风险误报（某类模式误判多） | 调整 `HIGH_RISK_PATTERNS` 或降级 |

调整后通过新 PR 评审验证，误判率回落则确认有效。

## 五、验证闭环

- 每次评审写入记录 → 误判率可统计
- override 推翻 → 误判率分子增加
- 误判率 > 15% → 告警 → 人工修订规则 → 新规则经评审验证
