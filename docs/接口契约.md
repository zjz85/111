# 接口契约

## 文件说明

- **核心理念：** 保留《Vibe Coding 真解》核心原则（单一职责、边界明确、失败可追溯、可评审），精简冗余字段
- **适用场景：** 日常模块开发、快速迭代场景

---

## 1. 基础信息

| 项 | 内容 |
|---|---|
| 契约 ID | 模块 - 接口 - v 版本号，例：rule-search-v1.0 |
| 所属模块 | 归属模块 / 分层 |
| 当前版本 | vX.Y |

---

## 2. 职责边界

- **核心职责：** 一句话说明接口唯一功能
- **不做什么：** 明确 2-3 条边界外职责，杜绝范围蔓延
- **机制与策略：**
  - **机制（固定逻辑）：**
  - **策略（可配置/调整）：**

---

## 3. 接口定义

### 接口签名

```
函数名(参数: 类型) => 返回值类型
```

### 输入参数

| 参数名 | 类型 | 必填 | 说明（含约束） |
|---|---|---|---|
| param1 | string | 是 | 业务含义，非空，长度 ≤ 64 |
| param2 | int | 否 | 业务含义，默认 10，范围 [1,100] |

### 输出结构

```json
{
  "code": 0,
  "data": {
    "field1": "字段说明"
  }
}
```

### 异常语义

| 错误码 | 错误场景 | 触发条件 |
|---|---|---|
| 40001 | 参数非法 | 入参为空 / 格式错误 / 超约束 |
| 40401 | 资源不存在 | 查询目标无效 |
| 50001 | 系统异常 | 依赖服务 / 执行失败 |

---

## 4. 约束约定

- **架构约束：** 调用层级限制、是否有副作用、是否幂等
- **依赖约束：** 允许依赖的模块/服务，禁止引入的三方能力
- **性能约束：** 单次响应时间上限、返回数量限制

---

## 5. 验收检查项

- ✅ **正确性：** 主路径符合契约，异常场景全覆盖，无未声明副作用
- ✅ **可读性：** 命名与契约术语一致，边界分支清晰，无隐式逻辑
- ✅ **可维护性：** 职责不越界，无重复逻辑，机制与策略分离
- ✅ **可演进性：** 接口兼容扩展，依赖轻量，策略可独立调整
